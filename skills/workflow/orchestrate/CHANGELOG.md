# Changelog

## 0.5.1 - 2026-11-26

- **agy (Antigravity CLI) as a child harness** - `references/harnesses/agy.md`, checked live on agy 1.5.18 via hc: launch with a bare model ID plus `--effort` (a suffixed ID with `--effort` silently falls back to the default model, so a raw config ID loses its effort suffix), status reported to hc, trust is exact-path (no globs, no subfolders), so the launch line trusts the child's cwd (JSON-encoded with `jq`) for that session via `--settings`, which makes worktrees work without touching the user's config; writes outside the workspace need the user's settings. `harness: agy` in config.

## 0.5.0 - 2026-11-25

- **Brief by `hc send`** - hc children start as a bare TUI and get the brief as one `hc send`; no brief file unless the context doesn't fit a prompt. Launch, send and wait run as one backgrounded command. Harness launch lines lose the prompt, and the busy-marker submit check is gone.
- **Corrections by `hc send`** - one short message to a running child, any harness, instead of a restart. Never a new task. A brief refused at a trust dialog is resent once the user answers; after the waiter returns, the parent checks the report reflects late corrections.
- **Waiter `scripts/hc-wait-child.sh`** - done only when the report's last line is `END`, never on child status or hc notes. Exits 2 (exited), 3 (unknown), 4 (blocked), 5 (error), 124 (limit, default 30 min, so a child stuck on a question can't idle the parent).
- **Reminder names hc** - with `runner: hc` (repo file beats user file; invalid values fall through), the `ORCHESTRATE ACTIVE` line adds the hc rules.
- **Fix:** the `"$(cat <<'BRIEF' …)"` form ran backticked brief text as commands under macOS bash 3.2; briefs are read with `IFS= read -r -d ''`.

## 0.4.0 - 2026-11-20

- **Rule 7 sizes children by their inputs** - before each dispatch the parent estimates what the child must take in: docs, skills it loads, code nobody has mapped. Building in unmapped code goes to a scout + implementer pair by default. "Mapped" means checked against the current code in this run (a scout map, or files and line ranges the user gave): a plan's file list is not a map, since plans go stale and miss callers. The scout (scoped tier) writes a short map of files, line ranges, conventions and commands, and the implementer (multi-step tier) works from it. Nothing finer: worktree, stack, tests, commit and PR stay with the implementer. Mapped work stays one child.
- **Briefs inline what the child needs** - conventions, decisions and the relevant lines of a long doc go in the brief, with exact line ranges. No more "read <doc> in full", and a skill is named only when the child must run its workflow. The brief template drops "This task is sized for you to finish": a child whose inputs turn out much larger than its brief implies writes a map of what it found and what is left, then stops.
- **Multi-step defaults to medium effort** - xhigh is kept for the hardest single calls, as on the judgment tier.
- **The hook reminder names sizing** - the `ORCHESTRATE ACTIVE` line now shows multi-step at medium and adds the scout + implementer and inline-conventions hint.

## 0.3.0 - 2026-11-19

- **Works across harnesses** - children can run in claude, codex, opencode or cursor-agent. They default to the current harness, which the agent knows from its system prompt, so there is no detect step. SKILL.md is now harness-neutral: the Claude-only mechanics (Agent tool, `model` and `effort` params, `run_in_background`) moved to `references/harnesses/claude-code.md`.
- **One harness-neutral tier table** - each tier (bulk, scoped, multi-step, judgment) lists model short names in preference order across providers, and the target harness takes the first one its alias table supports. Effort is one abstract word per tier that each harness translates. The judgment tier keeps "xhigh only for the hardest calls, never high". GPT 6.2 models are excluded on purpose (gpt-6.1-sol and gpt-6-astra instead).
- **Two runners** - `native` (the harness's own subagent tool) is the default. `hc` runs each child in an interactive terminal: opt-in via config, automatic when a child must run in a different harness. `references/runners/hc.md` covers labels for herdr-app, the submit check (`hc wait --output "<busy marker>" --timeout 45` in the same command as the launch; a timeout with `status: working` still counts), fresh child instead of typing into a stuck one, `hc wait` never sleep, results via the report file, and never killing children unasked.
- **Per-harness reference files** - `references/harnesses/{claude-code,codex,opencode,cursor-agent}.md` share one layout: detect, native subagents, hc launch line, model alias table, effort translation, unattended permissions and trust prompt, busy marker, skills dirs and hook equivalent, status. Facts not checked locally stay marked UNVERIFIED or (S). cursor-agent (`--force`) and opencode (`--auto`) children need the user's go-ahead first. Only claude is partly verified. The claude file is `claude-code.md`, not `claude.md`: on a case-insensitive filesystem `claude.md` is `CLAUDE.md`, which Claude Code injects as project instructions.
- **Optional config** - `<repo>/.claude/orchestrate.yaml` overrides `~/.claude/orchestrate.yaml`, which overrides the built-ins, key by key. Keys: `runner`, `harness`, `tiers` (models, effort, pinned harness), `routes`, `hc.labels`, `protocol` (appended rules that may only tighten). A request that names a harness or model beats config. A repo file is trusted like the repo's CLAUDE.md, and its rules are disclosed to the user before the first dispatch. Annotated sample: `orchestrate.example.yaml`; rules: `references/config.md`.
- **Routed loading** - SKILL.md always; `config.md` only when a config exists; the runner and harness files per child; `references/brief-template.md` (new: the exact child brief, with the subagent rules and untrusted-content guidance children need because they don't load the skill) on the first dispatch.
- **Fallbacks are reported** - no tier model available → the harness default model; target harness or `hc` missing → the current harness, native, next model on the tier. The child's report says which applied.
- **Hook stays Claude-only** - `hook-install.md` now says so; the codex, opencode and cursor-agent hook points sit in their harness files as untested follow-ups. The reminder line names tiers instead of Claude models.
- **Goal first, compact files** - SKILL.md opens with the goal every rule serves: finish the task while keeping the parent's context window healthy, with children doing the execution at the cheapest tier that does it well. SKILL.md and every reference file are cut to facts, commands and tables, each fact stated once. The brief template is under 20 lines.
- **Rule 7 sizes children by context, not by step** - a child is one coherent chunk that fits comfortably in its own context and returns a short report, such as a module with its tests, a full review pass or a research question. Split only when a chunk would overflow a child's context or parts can run in parallel, and chain children only on real dependencies. This replaces 0.2.0's one-lookup-per-child granularity, which slowed runs down.
- **Children may background their helpers** - children may start their own children (native subagents or hc) in the background or foreground; 0.2.0's foreground-only wording read as a ban on subagents, and its background-only fallback is gone. One hard rule at every level: never report done or end the session while started work still runs. The root still dispatches in the background by default.

## 0.2.0 - 2026-11-08

- **Keep children small and finishable** - new delegation rule 7: one child is one concise task it can complete and report on in a single pass. Large steps from a composed skill (for example a plan phase) are split by the parent into bounded children. Children chain sequentially, with a fresh child per step, and partial work re-split instead of retried. Motivated by long-running subagents bloating context.
- **Background root, foreground below** - the root session dispatches children in the background by default so the user is never blocked, and everything below the root runs in the foreground. Children may spawn their own children for discrete steps, and every brief must carry these subagent rules because children do not load the skill.
- **Explicit foreground grandchildren** - children dispatch grandchildren explicitly in the foreground and wait for results, and do the step themselves if only background agents are available. The composed-skill example no longer prescribes steps such as committing.

## 0.1.0 - 2026-07-15

Initial release: a delegation-mode skill plus a sticky-reminder hook — full rulebook injected once at invocation, tiny per-prompt reminder on every prompt while active, session-keyed state flag (inspired by the caveman plugin).

- **Activation contract** — `disable-model-invocation: true` in frontmatter means the model can never self-invoke the skill; the only trigger is the `/orchestrate` slash command. Contract: arm on the exact `/orchestrate` slash command; disarm on `/orchestrate off` or "stop orchestrat…", case-insensitive.
- **Delegation protocol** — parent does only decomposition, briefing, judgment, and synthesis; everything else is dispatched to subagents by model tier (haiku bulk/low, sonnet research/medium, opus multi-step/xhigh, fable judgment/medium). Independent chunks go out as parallel Agent calls; work above a child's tier escalates back through the parent. No `model` frontmatter — the skill inherits the session's model so orchestration judgment stays at the parent's tier. Children handling fetched or external content must be briefed with prompt-injection defense guidance or dispatched via an already-defended skill.
- **Composability** — `/orchestrate /other-skill X` runs the referenced skill under the delegation rules: it defines the workflow, orchestrate defines who does the work.
- **Sticky reminder hook** — `scripts/orchestrate-reminder.sh` (UserPromptSubmit): the exact `/orchestrate` slash command sets a session-keyed flag under `${ORCHESTRATE_STATE_DIR:-${TMPDIR:-/tmp}}`; while set, every prompt gets a one-line `ORCHESTRATE ACTIVE` reminder; `/orchestrate off` or "stop orchestrat…" (case-insensitive) clears it. Both arm and disarm phrases are prefix-anchored. All failure paths (missing jq, malformed stdin, missing or path-unsafe session_id) exit 0 with empty stdout — the hook can never block prompt submission. Manual install via a documented `~/.claude/settings.json` snippet; auto-registration deferred to the future plugin packaging of this repo.
- **Tests** — zero-dependency `node:test` suite (`tests/orchestrate/hook.test.mjs`, 26 cases) covering activation, stickiness, off-form and case-sensitivity boundaries, state-dir resolution, per-session flag isolation, path-traversal guarding, and the never-block failure paths (including missing `jq`).
